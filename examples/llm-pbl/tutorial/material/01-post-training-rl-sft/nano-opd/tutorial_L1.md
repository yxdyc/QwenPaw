# nano-opd L1 — 真实序列模型上的 OPD：学生自采样 + 教师 token 级 logprob 打分

> **模块定位**：L0 在玩具网格上证明了「散度选择决定采样需求」——reverse KL 的
> 期望在学生分布下，所以必须学生自采样（on-policy 的算术由来）。L1 把同一机制
> 搬进**真实序列模型**：真实 tokenizer（字符级）、两个真实小 Transformer（教师
> 110K 参数 / 学生 4.9K 参数，22x 容量差）、教师 logprob 由真实前向算出、学生
> 用真实梯度下降训练。
>
> **K+1 起点（K = L0）**：知道 OPD 的「学生写、教师批」接口、知道 reverse KL
> 为什么必须 on-policy、知道 mode-seeking vs mode-covering 的算术来源。本节
> 推进到 K+1：在真实序列模型上验证 L0 的全部结论仍然逐字成立，并发现 L0
> 看不到的新现象——**相变动力学**（valid rate 在 step 240–299 之间从 0 跳到
> 0.17）与**指标选择**（有效率是二值量、收敛后差距消失；教师背书度是连续量、
> 全程保持区分度）。
>
> **反幻觉声明**：本文件无 mock——教师与学生的前向/反向/采样全部是真实 torch
> 计算。但任务本身是合成任务（双语言密码本），数字为现场实跑，不是任何真实
> 模型的 benchmark。

四个配方的指标含义（后面反复用）：

- **有效率** = 学生采样响应完全匹配 codebook A 或 codebook B 的比例——学生生成的东西有多大比例是「合法翻译」；
- **A 模占有效** = 在有效响应中，匹配 codebook A（小写）的比例——用来判断锁模（接近 0 或 1 = 锁一个模，接近 0.5 = 两模都覆盖）；
- **教师背书度** = 教师对学生采样序列的平均 token logprob——学生写出来的东西教师认不认账（连续量，越高越好）。

## 2. 任务：双语言密码本——镜像 L0 的双峰教师

L0 用一维网格上的双峰高斯做教师。L1 把它翻译成序列任务：

**输入**：4 位数字（如 `3141`）。
**输出**：翻译成两种合法语言之一——

- 模式 A：每位数字 → 2 个**小写**字母（codebook A，如 `3141 → pjtlvetl`）
- 模式 B：每位数字 → 2 个**大写**字母（codebook B，如 `3141 → KSGQBWGQ`）

两份密码本是固定置换（写死在代码里，保证跨机器复现），小写/大写天然不相交，
首字符就暴露模——和 L0 的「x=+3 是左模、x=−3 是右模」完全同构。

**教师**：对两种语言都学（训练时 A/B 各半），审计结果有效率 0.979、A 模
占比 0.550——近乎完美的双语者，两个模都打满分。合法序列背书 -0.072
nats/token vs 杂交序列（大小写强行交错）-7.194——差 7.122 nats，教师能
清晰区分合法与非法。

**学生**：d_model=16, nhead=2, 1 层 Transformer，只有 4,914 参数——教师的
1/22。这是**刻意的容量设置**（同 L0）：装不下两份密码本时，mode-covering
vs mode-seeking 的差异才显形。

**词表**：字符级 tokenizer，V=66（4 特殊符 + 10 数字 + 26 小写 + 26 大写）。
不用 BPE 是为了教学透明——每个字符对应一个 id，没有 subword 黑箱。

## 3. 2×2 因子设计：精确隔离两个变量

L0 有三条路线（SFT / forward KL / reverse KL），但「信号从哪来」和「优化
什么散度」两个变量混在一起。L1 用 2×2 因子设计把它们精确拆开：

| 配方 | 前缀/数据来源 | 监督信号 | 隔离了什么 |
|------|-------------|----------|-----------|
| **sft** | 教师采样序列（离线） | 硬标签 CE（MLE） | 最便宜的蒸馏 baseline |
| **kd** | 教师采样序列（teacher-forced） | token 级 forward KL（软标签） | 经典白盒 KD |
| **opd_off** | 教师采样序列（teacher-forced） | token 级 **reverse** KL | ← L0 的错误估计器同款 |
| **opd** | 学生自采样（on-policy） | token 级 **reverse** KL | ← MiniLLM/GKD 路线 |

**控制变量逻辑**：

- **kd vs opd_off**：信号源相同（都是教师序列），只换散度（forward → reverse）。
  测的是「同一批数据，优化目标变了会怎样」。
- **opd_off vs opd**：散度相同（都是 reverse KL），只换信号源（教师前缀 → 学生
  自采样）。测的是「L0 的核心定理——期望在谁下面，样本就必须从谁来」。
- **sft vs opd**：最朴素的蒸馏 vs 最完整的 OPD。测的是「学生写出来的东西，
  教师认不认账」。

四个配方共享同一初始学生权重、同一训练步数（300）、同一 batch size（32）、
同一学习率（2e-3）——任何差异只能来自配方本身。

## 4. 配方逐个走

### 4.1 SFT 蒸馏——抄范文

```python
def train_sft(student, teacher_data, steps, batch, lr, seed, device="cpu"):
    """教师离线采样数据集 + 硬标签 MLE。"""
    px, ry = teacher_data
    opt = torch.optim.Adam(student.parameters(), lr=lr)
    for _ in range(steps):
        idx = torch.randint(0, n, (batch,), generator=g)
        logits = student(torch.cat([px[idx], ry[idx, :-1]], dim=1))
        loss = F.cross_entropy(...)     # 硬标签 CE
        opt.zero_grad(); loss.backward(); opt.step()
```

教师先采 512 条序列（256 prompt × 2 条/prompt，A/B 混模），学生做 next-token
MLE。和 L0 一样：数据从两个模来，学生容量不够，只能学到一个「折中」分布。
结果：有效率 0.226，A 模占有效 0.664——**两个模都沾了一点，但哪个都不精**。

### 4.2 KD（forward KL）——软标签也救不了

```python
def train_kd(student, teacher, teacher_data, ..., reverse=False):
    """teacher-forced 教师序列 + token 级 KL。"""
    full = torch.cat([px[idx], ry[idx, :-1]], dim=1)
    t_logits = teacher(full)           # 教师给全词表分布
    s_logits = student(full)
    loss = token_kl(s_logits, t_logits, reverse).mean()
```

和 SFT 用同一批教师序列，但监督信号从硬标签换成教师的软分布（forward KL）。
经典白盒 KD 的标准形态。结果：有效率 0.263，比 SFT 略好——但 A 模占有效
0.638，仍然是「两模都沾」的 mode-covering 形态。软标签给了更多信息，但没
改变目标函数的 mode-covering 本质（同 L0 §5 的分析）。

### 4.3 opd_off——L0 错误估计器的真实模型版

```python
# 和 kd 完全相同的代码，只把 reverse=True 传进去
train_kd(student, teacher, teacher_data, ..., reverse=True)
```

同一批教师序列、同样的 token 级 KL，只是散度换成 reverse。**这就是 L0 §9
里「把 reverse KL 的期望错用教师样本估计」的真实模型版本。**

结果：有效率 0.053，A 模占有效 0.301——**几乎什么都没学到**。reverse KL
用在教师前缀上，教师的双模分布把学生往「两模中间」拽（同 L0 §7 的 +136.149
系统性偏差），学生既没锁模也没覆盖，直接瘫了。

### 4.4 OPD——学生自采样 + 教师打分

```python
def train_opd(student, teacher, pool, steps, batch, lr, seed, ...):
    """GKD 式 token 级 reverse KL on 学生自采样。"""
    for step in range(steps):
        px = prompts_all[idx]
        with torch.no_grad():
            resp = student.sample(px, RESP_LEN)     # ← 学生自采样（on-policy）
            full = torch.cat([px, resp], dim=1)
            t_logits = teacher(full)                # ← 教师打分（白盒，不生成、不求梯度）
        s_logits = student(full)
        loss = token_kl(s_logits[:, ...], t_logits[:, ...], reverse=True).mean()
        opt.zero_grad(); loss.backward(); opt.step()
```

**每一步**：学生就 batch 个 prompt 自采样完整响应（on-policy）→ 教师一次
前向给全词表分布（只打分）→ token 级 KL(q_S||p_T) 反传。采样前缀视为常数
（梯度不穿过采样过程，与 GKD 一致）。

结果：有效率 0.168，A 模占有效 **0.165**——**锁定了 codebook B（大写）**。
教师背书 -1.704，是四个配方里**最高的**（除 kd 的 -1.642 外——但 kd 的
背书是在教师自己的前缀上算的，不算学生自己写出来的东西）。

## 5. 机制深潜

### 5.1 L0 的算术定理在真实模型上逐字成立

L0 §7 证明了「reverse KL 的期望在学生分布下 → 必须学生自采样」。L1 的
2×2 设计把这条定理拆成两个可独立验证的对照：

**对照 a（固定信号源，换散度）**：kd(fwd) 有效率 0.263 vs opd_off(rev) 0.053。
同一批教师序列，forward KL 还能学一点（mode-covering 至少把质量摊开了），
reverse KL 在教师前缀上直接瘫——因为教师的双模分布对 reverse KL 的
zero-avoidance 惩罚变成了系统性拉力，把学生拽向两模之间的荒原。

**对照 b（固定散度，换信号源）**：opd_off(教师前缀) 0.053 vs opd(学生自采样)
0.168。同一个 reverse KL，只是把前缀从教师换成学生自己，行为从「瘫」变成
「锁模 + 教师背书最高」。这就是 L0 的算术定理在真实序列模型上的落点。

### 5.2 相变动力学：有效率不是渐变的

OPD 的训练曲线揭示了一个 L0 看不到的现象：

```
step    0: 有效率=0.000 | 教师背书=-9.342
step   60: 有效率=0.000 | 教师背书=-8.734
step  120: 有效率=0.000 | 教师背书=-7.539
step  180: 有效率=0.000 | 教师背书=-5.248
step  240: 有效率=0.000 | 教师背书=-3.820
step  299: 有效率=0.171 | 教师背书=-1.703
```

有效率在前 240 步一直是 0——学生写的东西没有一条完全合法。但教师背书度
在稳步上升（-9.3 → -3.8），说明学生的分布在逐渐向教师的高概率区靠拢。
然后在 240–299 之间的某个时刻，**相变发生**：学生突然开始产出完全合法的
序列，有效率从 0 跳到 0.17。

这像什么？像一个学徒在练了 240 天之后，突然从「没一句对」变成「每 6 句
对 1 句」。不是渐变的——是量变积累到某个临界点后的质变。

**教师背书度是先行指标**：它在有效率还是 0 的时候就已经在上升了。如果你
在 step 200 只看有效率，会以为学生什么都没学到；但背书度已经从 -9.3 升到
-5.2——学生在「接近正确」的方向上持续进步。

### 5.3 指标选择：为什么用背书度而不是有效率做 self-check

这是本模块的一个关键设计决策，也是 5 轮 self-check 调试的教训。

**有效率是二值量**：一个序列要么完全匹配 codebook A，要么完全匹配 codebook
B，要么都不匹配（0 或 1）。当两个配方都过了相变点、有效率都收敛到非零值时，
它们之间的差距变得很小且不稳定——在 base 环境里 opd(0.168) 甚至低于
sft(0.226)。如果用有效率做断言（`opd["valid"] > sft["valid"]`），会在某些
环境/seed 下失败。

**教师背书度是连续量**：即使序列不完全合法，教师也能给出「接近合法」的
序列较高的 logprob。背书度在整个训练过程中保持区分度——从 step 0 的 -9.3
到 step 299 的 -1.7，始终在变化，始终能区分不同配方。

更重要的是，**背书度有理论依据**：on-policy reverse KL 可以分解为

```
KL(q_S || p_T) = E_{x~q_S}[log q_S(x) - log p_T(x)]
               = -H(q_S) - E_{x~q_S}[log p_T(x)]
```

优化 reverse KL 等价于最大化教师对学生样本的背书度 `E_{x~q_S}[log p_T(x)]`
（加上学生自身的熵正则项）。所以 `opd["endorse"] > off["endorse"]` 和
`opd["endorse"] > sft["endorse"]` 不是经验猜测——是优化目标的直接推论。

**教训**：当理论能告诉你「哪个指标应该更高」时，用那个指标做断言。不要用
一个「看起来应该更高但实际上可能在某些阶段反转」的指标。

## 6. 与真实方法的对应

L1 的每一块在真实 OPD 系统里都有对应物：

| L1 组件 | 真实系统 | 对照锚点 |
|---------|---------|---------|
| 字符级 tokenizer（V=66） | BPE/SentencePiece tokenizer（V=32K–150K） | 机制同构，规模不同 |
| TinyLM（110K/4.9K 参数） | Qwen3-32B 教师 / Qwen3-8B 学生（22x → 4x） | 容量差是核心设置 |
| 双语言密码本任务 | 多风格/多能力蒸馏（如代码+数学+对话） | 双模 → 多模 |
| `student.sample()` 自采样 | vLLM/SGLang 推理引擎做 rollout | 吞吐问题同 nano-vllm-sglang L0 |
| `teacher(full)` 白盒打分 | 教师模型前向给 token logprob | 黑盒教师留 L3 |
| `token_kl(reverse=True)` | GKD 的 token 级 generalized JSD | 本文件是 GKD 框架的一个实例化 |
| 采样前缀视为常数 | GKD 的 straight-through 近似 | 序列级 score-function 版见 L0 |
| 2×2 因子设计 | 论文里通常只对比 sft vs opd | 本文件多给了 kd 和 opd_off 做机制隔离 |

**与经典锚点的精确对应**：

- **MiniLLM** [2306.08543]：reverse KL + 学生自采样 + **序列级** score-function
  梯度（REINFORCE）。L0 实现了序列级版本，L1 实现了**token 级**版本（方差更低，
  生产配方更常用）。
- **GKD** [2306.13649]：学生自采样 + 广义散度（含 JSD）。L1 的 `token_kl`
  就是 GKD 框架在 reverse KL 这一个点上的实例化；GKD 的广义化（JSD 在
  forward/reverse 之间插值）是 L2 的主题。
- **DistiLLM** [2402.03898]：学生生成前缀上的 token 级 loss + 自适应调度。
  L1 的 `train_opd` 和 DistiLLM 的核心循环同构，只是没加自适应 off-policy
  复用（L3 对照）。

## 7. 费曼：能不能讲给外行听

**类比：学徒考翻译执照**——有两种合法语言（小写密码本 / 大写密码本），
学徒只能精通一种（容量受限）。

- **SFT 蒸馏** = 学徒抄师傅的翻译范文 256 份。小写大写各半，抄出来的
  「平均风格」大小写混杂——考官（教师）不认账（背书 -1.774）。
- **forward KL (kd)** = 师傅把完整评分标准给学徒，学徒要保证「每种风格
  都沾一点」。一个脑子 cover 不了两套密码本，只能每套都学个大概——考官
  认账度略好于 SFT（-1.642），但本质上还是两不像。
- **reverse KL off-policy (opd_off)** = 学徒不自己翻译，反而去读师傅的
  翻译然后「反思」。反思方向系统性错误：师傅两套都做，学徒被拽回中间，
  几乎什么都没学到（有效率 0.053，背书 -2.461）。
- **OPD (opd)** = 学徒自己翻译，考官每份都打分（teacher logprob）。学徒
  很快发现：专精大写密码本，份份高分；大小写混杂，份份低分。于是专精
  大写（锁模 mode_a_frac=0.165）——写出来的东西考官最认账（背书 -1.704）。

**一句话版**（同 L0，但现在有了真实模型的证据）：OPD = 学生写作文、老师
批改——作文必须学生自己写，因为要批改的是学生写得出来的东西。L1 补充：
**批改的分数（教师背书度）比及格率（有效率）更能反映学习进度**。

**类比边界**：真实 OPD 里教师对每个 token 都打一次分（L1 也是），但真实
词表是 32K–150K（L1 是 66）；真实学生是 8B 参数（L1 是 4.9K）；真实任务
是开放域生成（L1 是封闭密码本）。机制同构，规模不同——L1 的结论是「在
真实序列模型上 L0 的机制仍然成立」，不是「真实 OPD 的效果就是这个数字」。

## 8. 思考题

1. **opd_off 为什么几乎什么都没学到（有效率 0.053）？** 提示：回看 L0 §7
   的算术——reverse KL 的期望在学生分布下，用了教师序列就等于用了错误的
   估计器。在 L0 里这个偏差是 +136.149（把学生拽离模）；在 L1 里，教师的
   双模分布对 reverse KL 的 zero-avoidance 惩罚变成了系统性拉力，把学生
   拽向「两模之间」——既不是小写也不是大写。

2. **kd 的教师背书（-1.642）比 opd（-1.704）还高——这不矛盾吗？**
   不矛盾。kd 的背书是在**教师自己采样的序列**上算的（teacher-forced），
   教师当然给自己的序列打高分。opd 的背书是在**学生自己采样的序列**上算的
   ——学生写出来的东西，教师当然打分更低。真正该比的是「学生写出来的东西，
   谁认账」——这正是 §5.3 的指标选择逻辑。

3. **相变（step 240–299 有效率从 0 跳到 0.17）说明什么？** 提示：OPD 的
   训练不是匀速的。前 240 步学生在「接近合法」的方向上走（背书度持续上升），
   但还没跨过「完全合法」的门槛。一旦跨过，有效率突然跳变。如果你在 step 200
   做 early stopping（只看有效率=0），会以为 OPD 没用——但背书度已经在 -5.2
   了。**指标选择直接影响你对训练状态的判断。**

4. **如果把学生容量加大（比如 d_model=64，和教师一样大），四个配方的差异
   会怎样？** 提示：回看 L0 §13 反例三——容量充足时三条路线趋同。在 L1 里，
   如果学生够大，能同时装下两份密码本，opd 就不需要锁模了，sft 也能覆盖两
   模。mode-seeking vs mode-covering 只在「装不下」时才是问题。

## 9. 反例与边界

1. **opd_off 的失败不是调参问题**：和 L0 §13 反例一完全同构——散度期望在
   谁下面，样本就必须从谁采。这条违反不得，违反了不是「慢一点」，是方向错。
   **教训：on-policy 是 reverse KL 的算术要求，不是工程偏好。**

2. **有效率在 OPD vs SFT 上可能反转**：在 base 环境里 opd(0.168) < sft(0.226)。
   这不意味着 SFT 比 OPD 好——有效率是二值量，SFT 的 mode-covering 策略让它
   在两模中间也能偶尔「蒙对」一个；而 OPD 锁模后只生成一个模的序列，对那个模
   的精确度更高（教师背书 -1.704 vs -1.774 证明了这一点）。**教训：指标选择
   决定结论方向——用背书度，不要用有效率做 OPD vs SFT 的对比。**

3. **合成任务的局限**：双语言密码本是封闭任务（只有两种合法输出），真实
   OPD 面对的是开放域生成。L1 的结论是「L0 的机制在真实序列模型上仍然成立」，
   不是「真实 OPD 的效果就是这个数字」。规模效应、多模态、课程学习等真实
   世界的复杂性留 L2–L3。

4. **白盒教师假设**：L1 假设教师能给出全词表分布（白盒）。真实场景中教师
   可能是黑盒 API，只给采样 token 的 logprob。这时配方要换成序列级 REINFORCE
   或 token 级 advantage 形式——与 nano-verl L1 的 importance sampling 相接，
   留 L3。

## 10. 阶梯预告

- **L2**：multi-teacher OPD——多教师分布融合 / 路由的最小机制。L1 只有一个
  教师（双语教师），L2 引入多个教师，学生要学会「什么时候听谁的」。只教机制
  类别（survey taxonomy 的分支），不追个别 2026 变体方法名。
- **L3**：对照生产配方（Qwen3 / MiMo-V2-Flash / Thinking Machines 报告）与
  survey taxonomy——divergence 设计、信号源（白盒/黑盒）、token 加权与效率
  稳定化。

**交叉引用**：on-policy 采样的吞吐问题 → [nano-vllm-sglang](../../03-data-distributed-rsi/nano-vllm-sglang/) L0；
off-policy 修正（importance sampling）→ [nano-verl](../nano-verl/) L1；
SFT 蒸馏的数据侧（模板 / loss mask）→ [nano-llamafactory](../nano-llamafactory/) L0；
GKD 的广义散度（JSD 插值）→ survey [2604.00626] §5 方法 taxonomy。

### 11.2 self-check 断言设计史（5 轮调试教训）

当前断言用**教师背书度**做核心比较（`opd["endorse"] > off["endorse"]`、
`opd["endorse"] > sft["endorse"]`），锁模阈值 0.80。这不是初始设计——是
5 轮调试后的最终形态。

**初始设计**：用有效率差距（`opd["valid"] > off["valid"] + 0.15`）
和锁模（`lock > 0.85`）同时做断言。问题：有效率差距和锁模程度不在同一训练
阶段共存——早期锁模在发展但有效率差距还没出现，后期有效率差距出现但锁模
还没到 0.85。两环境确定性 EXIT=1，跨 5 轮不收敛。

**redesign 逻辑**：
1. 问「理论上哪个指标应该单调地反映 OPD 的优势？」→ 教师背书度
   （on-policy reverse KL 直接优化这个量）。
2. 有效率是二值量，双方都过相变后差距消失 → 不适合做断言。
3. 锁模阈值从 0.85 降到 0.80（300 步刚过相变，锁模尚在发展，理论方向正确
   即可）。

**教训**：self-check 断言应该基于**理论预测**（「优化目标决定了背书度排序」），
而不是**经验猜测**（「OPD 的有效率应该比 SFT 高」）。前者在所有环境下都成立，
后者只在特定训练阶段成立。
