# nano-trinity-rft L1 — 真实小模型统一 SFT+RL：配置驱动两阶段 + checkpoint 衔接

> **本节抓的机制**：L0 的统一数据流 + 配置驱动，在**真实模型**上还成不成立？
> 答案是成立——但真实模型会讨回三笔 toy 里不存在的债：**探索会死**（SFT 把策略

## 2. 任务与模型：L0 的架构，真实的梯度

三组件与统一样本协议和 L0 **逐行同构**（`Sample`/`Explorer`/`Buffer`/`Trainer`/`run(cfg)`
同名同字段），升级的只有「策略」这一件东西：

| | L0 | L1（本节） |
|---|---|---|
| 策略 | 表格 softmax（6 ctx × 4 act，权重全 0 起步） | char-GPT：vocab 15、d=128、4 层 attn、权重绑定，799,360 参数 |
| action | 1 个离散选项 | 4 个 token 的序列（字母表 `abcd`，与 L0 的 4 action 分支因子对称） |
| reward | 环境 0/1 | rule-based dense：与 target 逐位匹配率 ∈ {0, .25, .5, .75, 1} |
| SFT loss | −log π(target\|c) | 真实交叉熵（响应 4 token + EOS，prompt 区不参与） |
| RL | REINFORCE + 组内均值 baseline | 同思想，token 级组内相对优势（§3.2） |

任务沿用 L0 的覆盖不对称：6 个 context（prompt `k0:`–`k5:`），每个有唯一 target
（seed 20260806 确定生成：`acbb daab bcbd | dcca bbba cbba`），**teacher 只覆盖
ctx 0–2**，ctx 3–5 是数据空洞。两个评测指标（每 ctx 贪心解码）：

- **exact**：4 位全对记 1，否则 0——严格口径；
- **characc**：逐位匹配率——连续口径，看「填到哪一步了」。

未训练模型贪心评测 exact=0.000、characc=0.000（`[0]`）——注意贪心基线是 0 而不是
L0 的 0.25：未训练模型的贪心输出是某个固定错误串，不会「均匀蒙对 1/4」。这个差别
让本节的算术更干净（§8），也让 RL 的探索问题更尖锐（§6.3）。

## 3. 实验 [1] 逐轮读：两阶段主干

### 3.1 SFT 阶段（r1–r3）：模仿一步到位，但只到 teacher 画线的地方

r1 就把 c0 拉到 1.00，r2 覆盖处全 1.00——真实梯度下的模仿和 L0 一样快。
r3 末态 characc=0.625，算术恰为 `(3×1.00 + 3×0.25)/6`：空洞处的 0.25 是哪来的？
不是蒙对的——是 SFT 把**格式**塑造了：响应位的输出落进字母表 `abcd` 之内，
4 位里碰巧有 1 位与 target 相同。SFT 教会了「怎么写答案」，没教会「答案是什么」——
这正是 [nano-llamafactory L0](../nano-llamafactory/tutorial_L0.md)「mask 边界」讨论的
labels 空间监督在序列生成里的投影。

### 3.2 RL 阶段（r4–r23）：逐位填洞，顺序是 c4 → c3 → c5

per-ctx 轨迹是本节最好读的一张图：r4 时 c4 先动（0.25→0.50），r6 时 c3/c5 跟上，
r9 三个空洞都到 0.75（各剩 1 位），r12 只剩 c5 的最后一位，r16 全线 1.00 并在终态
保持。填洞速度由每个位置的「组内对比信号」强弱决定——这是 token 级 credit
assignment：reward 逐位可分解，baseline 就逐位取组内均值（每 ctx 采 group=64 条，
第 j 位的优势 = 该位是否匹配 − 组内第 j 位匹配率均值）。L0 里每 context 只有 1 个
action，序列级=token 级，这个问题不存在；响应变成 4 token 的序列后，「功劳归谁」
成了必须做的选择（思考题 2 会看到选错的代价）。

两处诚实的记录：**r4 的 exact 掉到 0.167**（characc 却从 0.625 只降到 0.583）——
RL 第一步打乱了 SFT 刚学到的贪心输出（覆盖处 c1/c2 短暂掉到 0.75），但 characc
说明「内容只乱了一点」，这是贪心指标的量化噪声，不是退化；**r17 的 0.833 摆动**
同理（ε 探索底噪 + 贪心 argmax 的量化），r18 即恢复。结构断言（self-check）只落在
终态与趋势上，不落在单轮噪声带上——这条断言设计纪律与
[nano-slime L1](../nano-slime/tutorial_L1.md) §14 同源。

### 3.3 本配置的一个特殊点：SFT 阶段没有存量流入 RL 阶段

`[1]` 的 RL 轮 batch 全是 `0/xxx`（纯 RL 样本）。供给/需求算术：SFT 阶段每轮新产
120 条 × max_reuse 2 = 需求 240 槽位，而供给是 32×24 步 = 768 槽位/轮——供给远大于
需求，样本当轮训完，r3 末 buffer 恰为空。L0 的 r4「24/24 混批」现象在这里**不出现**，
不是机制丢了，是 regime 不同：把 sft_k 调到 140（需求 840 > 供给 768），存量立刻
跨阶段流入（`[5]` 的反向探针实测 r4 batch = sft 183/rl 585）。**跨阶段数据流是否
出现，是供给/需求的算术结果，不是开关**——这是 L0 §9 供需教训在真实循环里的再验证。
本节主干选无存量 regime 另有原因，见 §6.5。

## 4. 实验 [2]：checkpoint 衔接是逐位精确的

scaffold 原始的「几步优化」目标在这里兑现成完整形态：SFT 阶段产 checkpoint，
RL 阶段从 checkpoint 续训。ckpt 内容 = `model + optimizer + version + cfg + RNG 状态`，
9432 KB——算术对得上：799,360 参数 × 4B ≈ 3.1 MB 权重，Adam 带走两份动量
（exp_avg + exp_avg_sq）≈ 6.2 MB，合计 ~9.3 MB 加序列化开销。**优化器状态约为模型
两倍**，这就是「ckpt 为什么比模型大」的具体答案；真实系统里 ZeRO/FSDP 还要把它切片
（[nano-fsdp L1](../../02-pretraining-cpt/nano-fsdp/tutorial_L1.md) 的主题）。

衔接验证分三层，一层比一层强：

1. **贪心输出逐字一致**：load 进全新初始化的模型实例，6 个 ctx 的贪心解码与保存前
   逐字相同（`acbb daab bcbd acbb acbb acbb`）；
2. **评测与版本号一致**：exact=0.500、characc=0.625 与保存前逐位相等，version=26
   与 `[1]` 的 r3 账本一致；
3. **续训轨迹逐轮逐位一致**：从 ckpt 续 RL 20 轮，与 `[1]` 的 r4–r23 **20/20 轮
   exact/characc/version 全等**。

第 3 层为什么能精确相等？因为本配置 r3 末 buffer 恰为空（§3.3），于是「ckpt 续训」
与「不间断跑」的唯一差别就是走没走 save/load——权重、Adam 动量、版本号、全局 RNG
流全部从 ckpt 恢复，两条路径从此逐位重合。这不是「差不多」，是**逐位相等**——
checkpoint 的完整性因此可证伪：少存任何一样（比如 RNG 状态），轨迹就会分叉，
断言立刻咬穿。思考题 4 会让你用 sft_k=140 制造「buffer 非空」的情形，看两条
路径如何因数据流差异而分叉——权重相同、数据流不同，正是 Trinity 把 Buffer 独立成
第三组件（README L25）的理由：checkpoint 带走的是 Trainer 的状态，Buffer 有自己的
生命周期。

顺带读一行输出：`greedy@ckpt` 里 ctx 3–5 全部输出 `acbb`——ctx 0 的 target。
SFT 之后模型在没见过的 prompt 上输出**它最熟的答案**。这个「错误习惯」是下一节的
主角。

## 5. 实验 [3]：消融阶梯——与 L0 相同的结论，加上一个诚实的新现象

同样 20 轮预算，只改 config 字段（`sft_rounds`/`rl_rounds`/`mix`），循环代码一字不动：

- **sft_only**：r2 到 0.500 后 18 轮纹丝不动，末态 `[1 1 1 0 0 0]`——天花板由覆盖画死（§8）。
- **rl_only**：r1 为 0（冷启探索），r12 到 1.000，末态全 1。
- **sft_then_rl**：前期与 sft_only 重合（r1/r3 相同），r4 起 RL 填洞，r20 到 0.833。
- **mix**：r6 就到 1.000，**四个配方里最快**。

前两条与 L0 完全同构：**模仿快但被覆盖画死，探索慢但没有天花板**。但真实梯度给出
两个 toy 里没有的现象，必须诚实入账：

**现象一：rl_only 中途追平并反超 sft_then_rl**（r12：1.000 vs 0.667）。注意这不
推翻 warm start——前期（r1/r3）SFT 打底确实更快（代码有 assert），但 sft_then_rl
的中段要为 SFT 养成的错误习惯**付账**：§4 看到的 `greedy@ckpt` 里三个空洞全是
`acbb`，RL 阶段得先把这个深度固化的习惯拆掉，再学正确答案；rl_only 从未养成这个
习惯，直接在白纸上探索。「SFT 打底」的成本项——习惯固化——在 toy 里不存在
（表格策略每个 context 的权重独立，无习惯可固化），在共享权重的真实模型上是
真实的。这也解释了现象二：

**现象二：mix 最快**。mix 从第一轮就双信号共存：RL 探索在习惯固化**之前**就开始，
SFT 信号同时保住覆盖处——两头的好处都拿了。Trinity 的算法表里 mix 类是一等公民
（`algorithm_type: mix_chord`，README L123），本节的实测给出了它为什么存在的
一个具体理由。

**口径声明**：现象一/二的具体幅度（谁在第几轮反超、差多少）是本任务本 seed 的实测，
不是普适定量规律；可迁移的是**方向**——warm start 的优势在前期、习惯成本在中段、
mix 规避两者。换任务换规模，幅度必须重测。

## 6. RL 阶段的调试史：真实模型讨回的五笔债（本节机制深潜）

代码第一版是「L0 架构 + 真实模型」的直接翻译：序列级 advantage、无 KL、FIFO buffer、
全程一个 lr。它**不工作**——接下来的每个失败模式都有实测记录，每个修复都是被逼出来的。
这段历史本身就是本节的教学内容：toy 到真实的鸿沟具体长什么样。

### 6.1 崩溃一：没有 KL 锚定，负 advantage 把格式打碎

初版 RL 阶段：characc 从 0.625 一路掉到 0.333 平台，**连覆盖处都退化**。机制：
空洞处的样本大多全错，advantage 为负，梯度把这些响应的概率往下压——但「往下压」
不挑方向，概率质量被推出响应格式（字母表之外的 token）；共享权重一乱，覆盖处跟着
遭殃。这就是 GRPO 目标函数里要有 KL(π‖π_ref) 正则项（arXiv:2402.03300）的原因——
它把策略拴在 RL 起点（SFT 模型）附近，负 advantage 只能在锚周围重新分配质量，
不能把格式拆了。**toy 不需要 KL（表格策略每个 action 独立、更新有界），真实模型
需要——这是第一笔债。**

### 6.2 但 KL 的锚，在空洞处是错的

加了 KL（β=0.04/0.1）之后：覆盖处稳了，空洞却卡在 0.5 平台。机制：ref 是 SFT 模型，
而 SFT 模型在空洞处的输出恰恰是**错误习惯**（`acbb`）——KL 把策略往 ref 拉，
就是在把空洞往错误答案拉。平衡点被移向 ref 一侧，target 永远到不了。
本节的处置：**β=0**，把「保护已学行为」的职责交给别的机制（§6.3 的探索对比 +
§6.6 的低 lr）。注意这是**本任务的局部结论**：真实 RLVR 里 ref 与 target 大体同向
（SFT 打底是高质量的），KL 是防 reward hacking 的第一道闸，不能由本节外推「KL 没用」。

### 6.3 崩溃二（最隐蔽）：探索死亡

β=0 之后空洞仍然不动——而且 r5–r15 的指标**逐轮逐位冻结**（完美平台）。诊断跑
（SFT 3 轮后对空洞 ctx 采样）给出的证据链：

- 组内唯一响应数 unique ≤ 5/24（group=24）；
- 逐位置采样熵 ≈ 0（多数位置 p>0.99 集中在一个错误字符上，temp=4.0 也打不开）；
- 逐 token |advantage| ≈ 0（组内无方差 → 全零信号）；
- 三个空洞 ctx 的贪心输出全是 `acbb`——SFT 把模型坍缩成了单一错误吸引子。

组内相对优势的燃料是**组内方差**；策略一坍缩，方差归零，梯度归零，RL 停摆。
温度救不了（logit gap 太大），只有显式探索能救：**ε-探索**——每个响应位置以概率
ε=0.3 从字母表均匀采样（而不是跟策略走），组内方差被机制性保证。这是 Explorer
组件的设计自由度：Trinity 把 Explorer 独立成组件（README L23），采样策略本来就是
它职责内的旋钮。**核心教训：toy 世界里探索是免费的（L0 均匀初始化，天然处处探索）；
真实模型里探索是必须显式维护的机制——SFT 会系统性地摧毁它。**

### 6.4 崩溃三：重要性比率是个陷阱

ε-探索引入行为分布 q=(1−ε)π+ε·u，教科书反应是做重要性校正 ρ=π/q。实测结果：
空洞再次锁死。机制：探索发现的**低概率正确 token**恰被 IS 校正降权——按正文公式
手算：π≈0.02、ε=0.3、u=0.25（4 字母均匀）→ q=0.7×0.02+0.3×0.25≈0.089，
ρ=π/q≈0.22（prototype 实测 ρ≈0.27，彼时各位实际 π 略异于 0.02，量级一致）
——IS 校正把「策略自己想不到、但被探索发现是对的」的样本**降权**了。估计无偏
（ρ 校正的就是分布差），但动态上 sterile：策略永远学不动自己概率低的东西，
被锁回自身偏好。处置：**ε-探索样本不做比率校正**，朴素 REINFORCE 直接训——
梯度有偏（偏向探索分布），但探索的发现被真正学到。比率校正属于另一个问题域：
**陈旧样本**的校正（样本产生时的策略版本旧了），那是 [nano-verl L1](../nano-verl/tutorial_L1.md)
的 ratio+clip 的地盘；本节的样本都在同轮附近消费（§7 staleness 有界），用不上。
把「探索注入」和「陈旧校正」分开，是这一笔债的教训。

### 6.5 崩溃四与 regime 选择：SFT 存量回放会干扰填洞

把 SFT 阶段调成「需求>供给」（sft_k=140，存量跨阶段流入 RL batch，即 L0 r4 现象的
复刻），终态卡在 0.917：24 个位置里总有 1–2 个翻不过来，且每次跑卡在不同位置。
机制：RL 阶段 batch 里混着的 SFT 样本持续注入覆盖处的 CE 梯度，与填洞梯度在
共享权重上拉锯；低 lr 下拉锯变成僵持。而**无存量 regime**（本节主干，sft_k=40）
稳定到 1.000。所以主干选无存量 regime、把存量 regime 留作 `[5]` 的探针——
这不是回避，是把两个 regime 都实测后做的选择。**生产里 SFT 回放常用来防格式退化，
本任务里它反而干扰——要不要回放取决于任务重叠度与规模，又一次「幅度必须重测」。**

### 6.6 最后两颗螺丝：phase-aware lr 与探索退火

- **RL 阶段 lr×0.15**：RL 梯度噪声大、且直接干扰 SFT 已得行为，生产配方普遍给
  RL 更低的 lr。实测：3e-3 全程时覆盖处在 RL 阶段反复抖动；×0.15 后稳定。
- **探索退火**：ε 从 0.3 线性降到 ~0.1。末期若保持高 ε，底噪会让个别位置在
  贪心口径下来回跳（r17 式摆动放大）；退火让策略在终局定稿。

五笔债清完，才有 `[1]` 的曲线。这段历史的完整参数轨迹（哪一版死在什么指标上）
在 复现运行 账本里有摘要；教程里的每个数字都来自定稿版重跑。

## 7. Buffer 的两处 L1 升级 + 账本

**升级一：select 从 FIFO 改随机采样。** prototype 实测：FIFO + 按 context 成块到达
会让 batch 偏食单一 context（一轮只训一个 ctx，梯度饥饿）；真实 buffer 的 select
是采样而非排队。本节用全局 RNG 的随机采样（固定 seed 下仍确定），并把 explorer 的
到达顺序改为跨 context 交错——双保险。

**升级二：账本字段。** `[5]` 的恒等式是 buffer 的「资产负债表」：

```text
进入 8040 条 | 训练 16071 次（sft 720 + rl 15351）| 退役 8031 条 | 现存 9 条
恒等式: 进入×max_reuse = 16080 = 训练 16071 + 现存潜在 9 + 容量驱逐损失 0 ✓
```

读法：每条样本最多训 max_reuse=2 次，所以「进入×2」是总潜在训练次数；它被三项
分完——已训的、现存样本还没训的、容量驱逐时白白损失的。本节无驱逐（容量 1024
够用），恒等式逐项对上。**staleness 实测**：RL 样本训练时的版本差 mean=12.72、
max=48——每轮约 24 个版本，均值≈半轮、最大≈2 轮（随机采样下个别样本被拖到下一轮
才消费）。对照 [nano-slime L1](../nano-slime/tutorial_L1.md)：那里 staleness 是
生成/训练解耦的产物；这里没有解耦，staleness 纯粹来自「采样顺序的随机性」——
同一个词，两种来源。真实系统里只要样本不是「现产现训」，staleness 就在，
差别只在量级与是否校正（nano-verl L1 的 ratio）。

**跨阶段存量探针**（`[5]` 末行）：sft_k=140 时需求 840 > 供给 768，r4（RL 第一轮）
batch = sft 183/rl 585——上一阶段的 SFT 存量流进了 RL 阶段，L0 r4「24/24」现象的
真实版。存量是否跨阶段，是供需算术的结果（§3.3）。

## 8. 实验 [4]：天花板算术，与 L0 的 0.625 完美镜像

sft_only 跑满 20 轮：exact=0.500、characc=0.625，末态 `[1 1 1 0 0 0]`。两个数都是
算术：

- exact = (3×1.0 + 3×0)/6 = **0.500**（覆盖处全对，空洞处贪心全错）；
- characc = (3×1.0 + 3×0.25)/6 = **0.625**（空洞处 4 位里恰 1 位碰巧匹配）。

而 L0 的天花板是 (3×1.0 + 3×0.25)/6 = 0.625——**同一个 0.625，两个口径**：
L0 的 0.25 是均匀策略的 reward 期望（4 action 蒙对 1/4），L1 的 0.25 是格式塑造后
的逐位 chance（4 字母碰对 1/4）。toy 与真实模型在「天花板由数据覆盖决定」这件事上
给出同一个数——机制的普适性最好的证据，就是不同实现落在同一条算术上。
结论不变：**看到 SFT loss 还在降、eval 贴住不动，先查 teacher 覆盖，别加轮数。**

## 9. 费曼自检

**类比：还是那家考前辅导班（L0），但学生换成了真人。** L0 的学生是一张答题卡
（表格策略）：每道题的对错互不相干，课表（config）一改，训练方式就换。L1 的学生
有个**真实的脑子**（共享权重），于是多出三件答题卡上不会发生的事：

1. **坏习惯**：老师只讲过前三种题型，学生把最熟的一种（`acbb`）背得滚瓜烂熟，
   之后见到没见过的题型，提笔就默写它（§4 的 `greedy@ckpt`）。补课（RL）得先拆
   习惯再学新东西——所以先上课的学生中段反而被没上课的追平（§5 现象一）。
2. **必须逼自己乱写**：学生一旦固化，自己写出的答案千篇一律，对答案也找不出
   对比（组内方差=0）。得立规矩：每写 4 个字母，逼自己随机乱写 1 个多（ε-探索），
   才有「哦原来这样写是对的」的发现（§6.3）。答题卡不需要这条规矩——它本来就是
   随机蒙的（toy 探索免费）。
3. **学新忘旧**：脑子是共用的，练新题型的笔迹会干扰旧题型（§6.5 的拉锯）。
   处方：练新题时轻一点（低 lr）、别把旧题反复塞进来（无存量 regime）。

**类比的边界**：真实 RFT 的「习惯」不是背串答案，而是整个生成分布的偏移
（风格、格式、推理套路）；「乱写」对应高温采样/多样性机制；「学新忘旧」对应
catastrophic forgetting 与 KL 锚定——方向同构，量级与手段都不同。

**自检三问**（讲不出就回对应小节）：

1. checkpoint 里为什么要存 RNG 状态？少存它，`[2]` 的哪条断言会咬穿？（§4）
2. 探索死亡为什么温度救不了、ε 能救？（§6.3：logit gap 与机制性方差）
3. 0.500 和 0.625 各是怎么算出来的？它们和 L0 的 0.625 是什么关系？（§8）

## 10. 思考题

1. **探索开关**：把 `BASE` 的 `eps` 改成 0 跑 `sft_then_rl`。先预测 RL 阶段曲线
   形状，再跑——对照 §6.3 的诊断四件套（unique/熵/|adv|/平台），说明为什么
   「组内方差」是这类算法的燃料。
2. **比率的代价**：在 `Trainer.step` 的 RL 分支给 `tok_logp` 乘上
   `ρ=(π_now/q).detach()`（q=(1−ε)π_gen+ε/4，需要在采样时记录 π_gen）。手算一个
   低概率正确 token 的 ρ（π=0.02、ε=0.3、u=0.25：先算 q≈0.089，再算 ρ=π/q），
   解释为什么「无偏」的校正会把空洞
   锁死（§6.4 实测）。进一步：nano-verl L1 的 ratio 为什么不会遇到这个陷阱？
   （提示：它校正的是什么分布差？）
3. **回放的两面**：把 `sft_k` 改成 140 跑 `sft_then_rl`（存量 regime）。终态停在
   哪、卡在哪类位置？（§6.5 实测 0.917。）生产配方里 SFT 回放常用来防格式退化——
   结合本实验，说清「什么时候回放是药、什么时候是毒」的判断变量。
4. **checkpoint 不保存 buffer**：把 `sft_k` 改成 140 再跑 `[2]` 的衔接实验。此时
   「ckpt 续训」与「不间断跑」还逐位相等吗？差异从哪一轮开始、为什么？
   （提示：r3 末 buffer 非空；两条路径的数据流从 r4 分叉，权重初值相同。）
   这个思想实验说明了 Trinity 把 Buffer 独立成组件的什么道理？

## 11. 反例与边界

1. **绝对值不可外推**：0.8M 参数、6 个 context、4 字符响应、CPU 两分钟——所有
   轮数/幅度/超参（ε=0.3、lr×0.15、group=64）都是这个口径的实测值。方向是机制
   给的（探索会死、习惯有成本、天花板由覆盖画死），幅度换模型换任务必须重测。
2. **中途反超不是普适规律**：rl_only@r12 反超 sft_then_rl 是本任务本 seed 的实测
   现象（结构方向可复述：warm start 前期快、习惯成本中段付），不要引用成
   「RL 总是比 SFT→RL 快」——真实生产里 SFT 打底几乎是标配，因为真实任务的探索
   比本节贵几个量级（§6 的 ε 在本节是 30%，在真实 RLVR 里不可能这么高）。
3. **token 级 advantage 依赖 dense reward**：本节的 reward 逐位可分解，advantage
   才能逐位算。真实 RLVR 大多是稀疏的序列级 0/1（解出来/没解出来），credit
   assignment 难得多——那是 L2 的主题，本节的「逐位」是特殊待遇，不是常态。
4. **β=0 是局部结论**：本任务的 ref 在空洞处是错的，KL 才变成阻力。真实场景 ref
   与目标大体同向，KL 是防 reward hacking 的第一道闸。由本节外推「KL 没用」会
   在真实系统里出事故。
